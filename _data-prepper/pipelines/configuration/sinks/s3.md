# S3 接收器

`s3` 接收器 (sink) 會將 OpenSearch Data Prepper 事件的批次儲存並寫入 Amazon Simple Storage Service (Amazon S3) 物件。設定的 `codec` 會決定 `s3` 接收器如何將資料序列化至 Amazon S3。

`s3` 接收器在批次處理事件時使用下列格式：

```
${pathPrefix}events-%{yyyy-MM-dd'T'HH-mm-ss'Z'}-${currentTimeInNanos}-${uniquenessId}.${codecSuppliedExtension}
```
{% include copy.html %}

當一批物件寫入 Amazon S3 時，物件的格式類似下列內容：

```
my-logs/2023/06/09/06/events-2023-06-09T06-00-01-1686290401871214927-ae15b8fa-512a-59c2-b917-295a0eff97c8.json
```
{% include copy.html %}

如需如何設定物件的詳細資訊，請參閱[物件鍵](#object-key-configuration)。

## 使用方式

下列範例會建立一個設定了 `s3` 接收器的管線。其中包含用於自訂管線事件與大小閾值的其他選項，並將編解碼器類型設為 `ndjson`：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        max_retries: 5
        bucket: bucket_name
        object_key:
          path_prefix: my-logs/%{yyyy}/%{MM}/%{dd}/
        threshold:
          event_count: 10000
          maximum_size: 50mb
          event_collect_timeout: 15s
        codec:
          ndjson:
        buffer_type: in_memory
```
{% include copy.html %}

## IAM 權限

若要使用 `s3` 接收器，請設定 AWS Identity and Access Management (IAM)，以授予 Data Prepper 寫入 Amazon S3 的權限。您可以使用類似下列 JSON 組態的設定：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "s3-access",
            "Effect": "Allow",
            "Action": [
              "s3:PutObject"
            ],
            "Resource": "arn:aws:s3:::<YOUR-BUCKET>/*"
        }
    ]
}
```

## 跨帳戶 S3 存取<a name="s3_bucket_ownership"></a>

當 Data Prepper 從 S3 儲存貯體擷取資料時，會使用[儲存貯體擁有者條件](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucket-owner-condition.html)驗證儲存貯體擁有權。

根據預設，S3 接收器不需要 `bucket_owners`。如果設定了 `bucket_owners`，且某個儲存貯體未包含在任一對應的組態中，則 `default_bucket_owner` 會預設為 `aws.sts_role_arn` 中的帳戶 ID。您可以同時設定 `bucket_owners` 與 `default_bucket_owner`，並一併套用這些設定。

從多個具有不同帳戶關聯的 S3 儲存貯體匯入資料時，請根據下列條件為跨帳戶 S3 存取設定 Data Prepper：

- 對於屬於相同帳戶的 S3 儲存貯體，將 `default_bucket_owner` 設為該帳戶的 ID。
- 對於屬於多個帳戶的 S3 儲存貯體，請使用 `bucket_owners` 對應。

`bucket_owners` 對應會為屬於多個帳戶的儲存貯體指定帳戶 ID。例如，在下列組態中，`my-bucket-01` 由 `123456789012` 擁有，而 `my-bucket-02` 由 `999999999999` 擁有：

```yaml
sink:
  - s3:
      default_bucket_owner: 111111111111
      bucket_owners:
        my-bucket-01: 123456789012
        my-bucket-02: 999999999999
```

## 組態 

自訂 `s3` 接收器時，請使用下列選項。

選項 | 必要 | 類型                                            | 說明
:--- |:---------|:------------------------------------------------| :---
`bucket` | 視情況 | 字串                                          | 指定接收器的 S3 儲存貯體名稱。支援使用 [Data Prepper 運算式]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/) 動態命名儲存貯體，例如 `test-${/bucket_id}`。若動態儲存貯體無法存取且未設定 `default_bucket`，則會捨棄物件資料。未設定 `bucket_selector` 時為必要。不能與 `bucket_selector` 一起使用。
`bucket_selector` | 視情況 | [儲存貯體選擇器](#bucket-selector)        | 決定接收器將物件寫入哪個儲存貯體與路徑前置詞的外掛程式。未設定 `bucket` 時為必要。不能與 `bucket` 一起使用。
`default_bucket` | 否       | 字串                                          | 當 `bucket` 中的動態儲存貯體無法存取時所使用的靜態儲存貯體。 
`bucket_owners` | 否       | Map                                             | 儲存貯體名稱與其帳戶擁有者 ID 的對應，用於跨帳戶存取。請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。 
`default_bucket_owner` | 否       | 字串                                          | S3 儲存貯體擁有者的 AWS 帳戶 ID。請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。 
`codec` | 是      | [編解碼器](#codec)                                 | 將資料序列化至 S3 物件中。
`aws` | 是      | AWS                                             | AWS 組態。請參閱 [`aws`](#aws)。
`threshold` | 是      | [閾值](#threshold-configuration)           | 將物件寫入 S3 的條件。 
`aggregate_threshold` | 否       | [彙總閾值](#aggregate-threshold-configuration) | 使用動態 `path_prefix` 時排清物件的條件。 
`object_key` | 否       | [物件鍵](#object-key-configuration)         | 設定物件儲存的 `path_prefix` 與 `name_pattern_prefix`。預設的物件名稱模式為 `events-%{yyyy-MM-dd'T'HH-mm-ss'Z'}`。根據預設，這些物件位於儲存貯體的根目錄中。
`object_metadata` | 否       | [物件中繼資料](#object-metadata)             | 要新增至每個 S3 物件的使用者定義中繼資料。不能與 `predefined_object_metadata` 一起使用。
`predefined_object_metadata` | 否       | [物件中繼資料](#object-metadata)             | 要新增至每個 S3 物件的使用者定義中繼資料。不能與 `object_metadata` 一起使用。
`compression` | 否       | 字串                                          | 壓縮演算法：`none`、`gzip` 或 `snappy`。預設為 `none`。 
`buffer_type` | 否       | [緩衝區類型](#buffer-type)                     | 緩衝區類型組態。 
`max_retries` | 否       | 整數                                         | S3 匯入請求的最大重試次數。預設為 `5`。
`client` | 否       | [用戶端](#client-configuration)                 | 接收器用來連線至 Amazon S3 的 HTTP 用戶端組態。
`server_side_encryption` | 否       | [伺服器端加密](#server-side-encryption) | 寫入 S3 之物件的伺服器端加密設定。

## `aws`

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`region` | 否 | 字串 | 用於認證資訊的 AWS 區域。預設為[判斷區域的標準 SDK 行為](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/region-selection.html)。
`sts_role_arn` | 否 | 字串 | 對 Amazon Simple Queue Service (Amazon SQS) 與 Amazon S3 的請求所要擔任的 AWS Security Token Service (AWS STS) 角色。預設為 `null`，其使用[取得認證資訊的標準 SDK 行為](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html)。
`sts_header_overrides` | 否 | 對應 | 接收器外掛程式擔任 IAM 角色時所使用的標頭覆寫值對應。
`sts_external_id` | 否 | 字串 | Data Prepper 擔任該角色時所使用的 AWS STS 外部 ID。如需詳細資訊，請參閱 AWS STS API 參考中 [AssumeRole](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html) 下的 `ExternalId` 一節。

## 閾值組態

使用下列選項為 `s3` 接收器 (sink) 設定匯入閾值。當發生下列任一情況時，Data Prepper 會將事件寫入 S3 物件。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`event_count` | 否 | 整數 | 將物件寫入 S3 之前要累積的 Data Prepper 事件數量。有效值為 0 到 10,000,000。若設為 `0` 或未設定，事件數量不會觸發寫入。
`maximum_size` | 否 | 字串 | 將物件寫入 S3 之前要累積的最大位元組數。預設值為 `50mb`。
`event_collect_timeout` | 是 | 字串 | Data Prepper 將事件寫入 S3 之前的最長時間。此值應為 ISO-8601 持續時間（例如 `PT2M30S`），或簡易表示法（例如 `60s` 或 `1500ms`）。有效值為 1 秒到 1 小時。

## 彙總閾值組態

使用下列選項來設定規則或限制，當彙總值超過定義的閾值時觸發特定動作或行為。

選項 | 必要 | 類型 | 說明
:--- |:-----------------------------------|:-------| :---
`flush_capacity_ratio` | 否 | 浮點數 | 當達到 `aggregate_threshold maximum_size` 時強制排清的群組百分比。百分比以 `0.0` 到 `1.0` 之間的數字表示。預設為 `0.5`。
`maximum_size` | 是 | 字串 | 在強制排清物件前可累積的最大位元組數。例如 `128mb`。

## 緩衝區類型

`buffer_type` 是選用的組態，決定 Data Prepper 在將物件寫入 S3 前如何暫時儲存資料。預設值為 `in_memory`。

使用下列其中一個選項：

- `in_memory`：將記錄儲存在記憶體中。
- `local_file`：將記錄排清到本機機器上的檔案。此選項使用機器的暫存目錄。
- `multipart`：使用 [S3 分段上傳](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)寫入。每 10 MB 會寫成一個部分。

## 物件金鑰組態

使用下列選項定義儲存於 S3 之物件的物件金鑰建構方式。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`path_prefix` | 否 | 字串 | 寫入 S3 的物件所使用的 S3 金鑰字首路徑。接受日期時間格式，並可使用 [Data Prepper 運算式]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/) 動態插入值。例如，您可以使用 `/${/my_partition_key}/%{yyyy}/%{MM}/%{dd}/%{HH}/`，根據 `my_partition_key` 值在 S3 中建立每小時的資料夾。字首路徑應以 `/` 結尾。根據預設，Data Prepper 會將物件寫入 S3 儲存貯體的根目錄。
`name_pattern_prefix` | 否 | 字串 | 物件名稱的字首。接收器會在此字首後附加 `-%{yyyy-MM-dd'T'HH-mm-ss'Z'}`，接著是唯一 ID 與編解碼器副檔名。例如，將 `name_pattern_prefix` 設定為 `app-logs` 會產生 `app-logs-2026-06-09T06-00-01Z-1686290401871214927-ae15b8fa-512a-59c2-b917-295a0eff97c8.json` 之類的物件名稱。支援 [Data Prepper 運算式]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)，例如 `app-${/service}`。不能包含日期時間模式（`%{...}`）。預設值為 `events`。

## 物件中繼資料

使用下列選項，為每個 S3 物件新增使用者定義的中繼資料。只有當 `buffer_type` 為 `in_memory` 時，接收器才會新增中繼資料。

`object_metadata` 物件支援下列選項。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`number_of_events_key` | 否 | 字串 | 接收器用來儲存物件中事件數量的中繼資料索引鍵名稱。

`predefined_object_metadata` 物件支援下列選項。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`number_of_objects` | 否 | 字串 | 接收器用來儲存物件中事件數量的中繼資料索引鍵名稱。

## 用戶端組態

使用下列選項設定接收器 (sink) 用來連線至 Amazon S3 的 HTTP 用戶端。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`max_connections` | 否 | 整數 | 與 Amazon S3 的最大並行連線數。預設為 `50`。
`acquire_timeout` | 否 | 字串 | 等待連線可用的最長時間。值應為 ISO-8601 持續時間（例如 `PT30S`），或簡單表示法（例如 `30s` 或 `1500ms`）。預設為 `10s`。

## 伺服器端加密

使用下列選項，為寫入 S3 的物件設定伺服器端加密。如需詳細資訊，請參閱 Amazon S3 文件中的[使用伺服器端加密保護資料](https://docs.aws.amazon.com/AmazonS3/latest/userguide/serv-side-encryption.html)。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`type` | 否 | 字串 | 伺服器端加密類型。有效值為 `s3`（使用 Amazon S3 受管金鑰的伺服器端加密）、`kms`（使用 AWS Key Management Service (AWS KMS) 金鑰的伺服器端加密）及 `kms_dsse`（使用 AWS KMS 金鑰的雙層伺服器端加密）。預設為 `s3`。
`kms_key_id` | 否 | 字串 | 用於加密物件的 AWS KMS 金鑰 ID 或 Amazon Resource Name (ARN)。僅在 `type` 為 `kms` 或 `kms_dsse` 時適用。若未設定，Amazon S3 會使用 AWS 受管金鑰。
`bucket_key_enabled` | 否 | 布林值 | 是否使用 S3 Bucket Key 加密物件。僅在 `type` 為 `kms` 或 `kms_dsse` 時適用。預設為 `true`。

下列範例使用 AWS KMS 金鑰加密物件：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        bucket: my-bucket
        server_side_encryption:
          type: kms
          kms_key_id: arn:aws:kms:us-east-1:123456789012:key/1234abcd-12ab-34cd-56ef-1234567890ab
        threshold:
          event_collect_timeout: 60s
        codec:
          ndjson:
```

## 儲存貯體選取器

`bucket_selector` 選項會指定一個外掛程式，用來決定接收器 (sink) 所寫入物件的儲存貯體 (bucket) 與路徑前置詞。設定 `bucket_selector` 時，接收器會忽略 `object_key.path_prefix`。唯一支援的儲存貯體選取器是 `aws_security_lake`。

### `aws_security_lake`

`aws_security_lake` 儲存貯體選擇器會將物件寫入 [Amazon Security Lake](https://docs.aws.amazon.com/security-lake/latest/userguide/what-is-security-lake.html)。接收器 (sink) 啟動時，會在 Security Lake 中建立自訂記錄來源，並將物件寫入該來源的 S3 位置。每個物件的路徑前綴由自訂來源位置加上 `region=<region>/accountId=<account_id>/eventDay=<yyyyMMdd>/` 組成，其中區域為 `aws.region`，帳戶 ID 取自 `aws.sts_role_arn`，日期則為接收器啟動當天的日期。`aws.sts_role_arn` 選項為必要項目，會用作自訂來源的爬蟲程式角色。

Security Lake 用戶端會使用預設的 AWS 認證資訊提供者鏈和區域提供者鏈來建立自訂來源，因此必須能取得區域資訊，例如透過 `AWS_REGION` 環境變數提供。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`log_class` | 是 | 字串 | 寫入自訂來源之資料的 Open Cybersecurity Schema Framework (OCSF) 事件類別，例如 `NETWORK_ACTIVITY`。
`source_name` | 否 | 字串 | 自訂記錄來源的名稱。接收器會在此名稱後附加四個隨機字元。若未設定，接收器會產生隨機名稱。
`source_version` | 否 | 字串 | 自訂記錄來源的版本。預設為 `1.0`。
`external_id` | 否 | 字串 | 自訂來源提供者身分的外部 ID。預設為 `extid`。

以下範例會將 Parquet 物件寫入 Security Lake 自訂來源：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        bucket_selector:
          aws_security_lake:
            source_name: my-source
            log_class: NETWORK_ACTIVITY
        threshold:
          event_collect_timeout: 60s
        codec:
          parquet:
            auto_schema: true
```

## `codec`

`codec` 決定 `s3` 來源如何格式化寫入每個 S3 物件的資料。

### `avro` 編解碼器

`avro` 編解碼器會將事件寫成 [Apache Avro](https://avro.apache.org/) 文件。由於 Avro 需要結構描述，您可以自行定義結構描述，或讓 Data Prepper 自動產生。建議自行定義結構描述，因為這樣可以針對您的特定使用情境加以調整。

當您提供自己的 Avro 結構描述時，該結構描述會定義資料的最終結構。任何傳入事件中未對應到 Avro 結構描述的額外值，都不會包含在最終目的地中。Data Prepper 不允許在自訂結構描述時使用 `include_keys` 或 `exclude_keys`，以避免自訂 Avro 結構描述與 `include_keys` 或 `exclude_keys` 接收器組態之間的混淆。

當您的資料是同質的，您可以自動產生結構描述。自動產生的結構描述以編解碼器收到的第一個事件為基礎。結構描述只會包含該事件中的鍵，且所有鍵都必須存在於所有事件中，才能自動產生可用的結構描述。自動產生的結構描述會將所有欄位設為可為 null。使用 `include_keys` 和 `exclude_keys` 接收器組態來控制自動產生的結構描述中包含哪些資料。

Avro 欄位應使用 null [聯集](https://avro.apache.org/docs/1.12.0/specification/#unions)，因為這樣可以允許缺少值。否則，每個事件都必須包含所有必要欄位。僅在確定欄位一定存在時才使用不可為 null 的欄位。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`schema` | 是 | 字串 | Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。若 `auto_schema` 設為 true 則不需要。
`auto_schema` | 否 | 布林值 | 設為 `true` 時，會從第一個事件自動產生 Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。
 
### `ndjson` 編解碼器

`ndjson` 編解碼器會將每一行寫成一個 JSON 物件。`ndjson` 編解碼器不接受任何組態。

### `json` 編解碼器

`json` 編解碼器會將事件寫入單一大型 JSON 檔案。每個事件會寫入 JSON 陣列中的一個物件。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`key_name` | 否 | 字串 | JSON 陣列的鍵名稱。預設為 `events`。

### `parquet` 編解碼器

`parquet` 編解碼器會將事件寫入 Parquet 檔案。使用此編解碼器時，請將 `buffer_type` 設為 `in_memory`。

`parquet` 編解碼器會使用結構描述寫入資料。由於 Parquet 需要 Avro 結構描述，您可以自行定義結構描述，或讓 Data Prepper 自動產生。建議自行定義結構描述，因為這樣可以針對您的特定使用情境加以調整。

如需 Avro 結構描述的詳細資訊，請參閱 [Avro 編解碼器](#avro-codec)。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`schema` | 是 | 字串 | Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。若 `auto_schema` 設為 true 則不需要。
`auto_schema` | 否 | 布林值 | 設為 `true` 時，會從第一個事件自動產生 Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。

### 使用 Parquet 設定結構描述

下列範例管線顯示如何設定 `s3` 接收器，以使用 [VPC Flow Logs](https://docs.aws.amazon.com/vpc/latest/userguide/flow-logs.html#flow-log-records) 的結構描述將 Parquet 資料寫入 Parquet 檔案：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        bucket: mys3bucket
        object_key:
          path_prefix: vpc-flow-logs/%{yyyy}/%{MM}/%{dd}/%{HH}/
        codec:
          parquet:
            schema: >
              {
                "type" : "record",
                "namespace" : "org.opensearch.dataprepper.examples",
                "name" : "VpcFlowLog",
                "fields" : [
                  { "name" : "version", "type" : ["null", "string"]},
                  { "name" : "srcport", "type": ["null", "int"]},
                  { "name" : "dstport", "type": ["null", "int"]},
                  { "name" : "accountId", "type" : ["null", "string"]},
                  { "name" : "interfaceId", "type" : ["null", "string"]},
                  { "name" : "srcaddr", "type" : ["null", "string"]},
                  { "name" : "dstaddr", "type" : ["null", "string"]},
                  { "name" : "start", "type": ["null", "int"]},
                  { "name" : "end", "type": ["null", "int"]},
                  { "name" : "protocol", "type": ["null", "int"]},
                  { "name" : "packets", "type": ["null", "int"]},
                  { "name" : "bytes", "type": ["null", "int"]},
                  { "name" : "action", "type": ["null", "string"]},
                  { "name" : "logStatus", "type" : ["null", "string"]}
                ]
              }
        threshold:
          event_count: 500000000
          maximum_size: 20mb
          event_collect_timeout: PT15M
        buffer_type: in_memory
```
