# S3 接收端

`s3` 接收端會將 OpenSearch Data Prepper 事件的批次儲存並寫入 Amazon Simple Storage Service (Amazon S3) 物件。設定的 `codec` 會決定 `s3` 接收端如何將資料序列化至 Amazon S3。

`s3` 接收端在批次處理事件時使用下列格式：

```
${pathPrefix}events-%{yyyy-MM-dd'T'HH-mm-ss'Z'}-${currentTimeInNanos}-${uniquenessId}.${codecSuppliedExtension}
```
{% include copy.html %}

當一批物件寫入 Amazon S3 時，物件的格式類似下列內容：

```
my-logs/2023/06/09/06/events-2023-06-09T06-00-01-1686290401871214927-ae15b8fa-512a-59c2-b917-295a0eff97c8.json
```
{% include copy.html %}

如需如何設定物件的詳細資訊，請參閱[物件金鑰](#object-key-configuration)。

## 使用方式

下列範例會建立一個設定了 `s3` 接收端的管線。其中包含用於自訂管線事件與大小閾值的其他選項，並將編解碼器類型設為 `ndjson`：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        max_retries: 5
        bucket: bucket_name
        object_key:
          path_prefix: my-logs/%{yyyy}/%{MM}/%{dd}/
        threshold:
          event_count: 10000
          maximum_size: 50mb
          event_collect_timeout: 15s
        codec:
          ndjson:
        buffer_type: in_memory
```
{% include copy.html %}

## IAM 權限

若要使用 `s3` 接收端，請設定 AWS Identity and Access Management (IAM)，以授予 Data Prepper 寫入 Amazon S3 的權限。您可以使用類似下列 JSON 組態的設定：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "s3-access",
            "Effect": "Allow",
            "Action": [
              "s3:PutObject"
            ],
            "Resource": "arn:aws:s3:::<YOUR-BUCKET>/*"
        }
    ]
}
```

## 跨帳戶 S3 存取<a name="s3_bucket_ownership"></a>

當 Data Prepper 從 S3 儲存貯體擷取資料時，會使用[儲存貯體擁有者條件](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucket-owner-condition.html)驗證儲存貯體擁有權。

根據預設，S3 接收端不需要 `bucket_owners`。如果設定了 `bucket_owners`，且某個儲存貯體未包含在任一對應的組態中，則 `default_bucket_owner` 會預設為 `aws.sts_role_arn` 中的帳戶 ID。您可以同時設定 `bucket_owners` 與 `default_bucket_owner`，並一併套用這些設定。

從多個具有不同帳戶關聯的 S3 儲存貯體匯入資料時，請根據下列條件為跨帳戶 S3 存取設定 Data Prepper：

- 對於屬於相同帳戶的 S3 儲存貯體，將 `default_bucket_owner` 設為該帳戶的 ID。
- 對於屬於多個帳戶的 S3 儲存貯體，請使用 `bucket_owners` 對應。

`bucket_owners` 對應會為屬於多個帳戶的儲存貯體指定帳戶 ID。例如，在下列組態中，`my-bucket-01` 由 `123456789012` 擁有，而 `my-bucket-02` 由 `999999999999` 擁有：

```yaml
sink:
  - s3:
      default_bucket_owner: 111111111111
      bucket_owners:
        my-bucket-01: 123456789012
        my-bucket-02: 999999999999
```

## 組態

自訂 `s3` 接收端時，請使用下列選項。

選項 | 必要 | 類型 | 說明
:--- |:---------|:------------------------------------------------| :---
`bucket` | 是 | 字串 | 指定接收端的 S3 儲存貯體名稱。支援使用 [Data Prepper 運算式]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)的動態儲存貯體命名，例如 `test-${/bucket_id}`。如果無法存取動態儲存貯體，且未設定 `default_bucket`，則會捨棄物件資料。
`default_bucket` | 否 | 字串 | 用於 `bucket` 中無法存取之動態儲存貯體的靜態儲存貯體。
`bucket_owners` | 否 | 對應 | 用於跨帳戶存取的儲存貯體名稱及其帳戶擁有者 ID 對應。請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。
`default_bucket_owner` | 否 | 字串 | S3 儲存貯體擁有者的 AWS 帳戶 ID。請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。
`codec` | 是 | [編解碼器](#codec) | 將 S3 物件中的資料序列化。
`aws` | 是 | AWS | AWS 組態。請參閱 [`aws`](#aws)。
`threshold` | 是 | [閾值](#threshold-configuration) | 將物件寫入 S3 的條件。
`aggregate_threshold` | 否 | [彙總閾值](#threshold-configuration) | 使用動態 `path_prefix` 排清物件的條件。
`object_key` | 否 | [物件金鑰](#object-key-configuration) | 設定物件儲存的 `path_prefix` 與 `file_pattern`。檔案模式為 `events-%{yyyy-MM-dd'T'hh-mm-ss}`。根據預設，這些物件會位於儲存貯體的根目錄中。`path_prefix` 可設定。
`compression` | 否 | 字串 | 壓縮演算法：`none`、`gzip` 或 `snappy`。預設為 `none`。
`buffer_type` | 否 | [緩衝區類型](#buffer-type) | 緩衝區類型組態。
`max_retries` | 否 | 整數 | S3 匯入請求的最大重試次數。預設為 `5`。

## `aws`

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`region` | 否 | 字串 | 用於憑證的 AWS 區域。預設為[判斷區域的標準 SDK 行為](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/region-selection.html)。
`sts_role_arn` | 否 | 字串 | 對 Amazon Simple Queue Service (Amazon SQS) 與 Amazon S3 的請求所要擔任的 AWS Security Token Service (AWS STS) 角色。預設為 `null`，其使用[取得憑證的標準 SDK 行為](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html)。
`sts_header_overrides` | 否 | 對應 | 接收端外掛程式擔任 IAM 角色時所使用的標頭覆寫值對應。
`sts_external_id` | 否 | 字串 | Data Prepper 擔任該角色時所使用的 AWS STS 外部 ID。如需詳細資訊，請參閱 AWS STS API 參考中 [AssumeRole](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html) 下的 `ExternalId` 一節。

## 閾值組態

使用下列選項來設定 `s3` 接收端的匯入閾值。當發生任一這些條件時，Data Prepper 會將事件寫入 S3 物件。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`event_count` | 是 | 整數 | 將物件寫入 S3 之前要累積的 Data Prepper 事件數。
`maximum_size` | 否 | 字串 | 將物件寫入 S3 之前要累積的最大位元組數。預設為 `50mb`。
`event_collect_timeout` | 是 | 字串 | Data Prepper 將事件寫入 S3 之前的最長時間。此值應為 ISO-8601 持續時間（例如 `PT2M30S`），或簡單標記法（例如 `60s` 或 `1500ms`）。

## 彙總閾值組態

使用下列選項來設定規則或限制，當彙總值超過定義的閾值時觸發特定動作或行為。

選項 | 必要 | 類型 | 說明
:--- |:-----------------------------------|:-------| :---
`flush_capacity_ratio` | 否 | 浮點數 | 當達到 `aggregate_threshold maximum_size` 時強制排清的群組百分比。百分比以 `0.0` 到 `1.0` 之間的數字表示。預設為 `0.5`。
`maximum_size` | 是 | 字串 | 在強制排清物件前可累積的最大位元組數。例如 `128mb`。

## 緩衝區類型

`buffer_type` 是選用的組態，決定 Data Prepper 在將物件寫入 S3 前如何暫時儲存資料。預設值為 `in_memory`。

使用下列其中一個選項：

- `in_memory`：將記錄儲存在記憶體中。
- `local_file`：將記錄排清到本機機器上的檔案。此選項使用機器的暫存目錄。
- `multipart`：使用 [S3 分段上傳](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)寫入。每 10 MB 會寫成一個部分。

## 物件金鑰組態

使用下列選項來定義儲存在 S3 中物件的物件金鑰建構方式。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`path_prefix` | 否 | 字串 | 寫入 S3 的物件所使用的 S3 金鑰前置路徑。接受日期時間格式，並可使用 [Data Prepper 運算式]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)動態注入值。例如，您可以使用 `/${/my_partition_key}/%{yyyy}/%{MM}/%{dd}/%{HH}/` 根據 `my_partition_key` 值在 S3 中建立每小時資料夾。前置路徑應以 `/` 結尾。根據預設，Data Prepper 會將物件寫入 S3 儲存貯體根目錄。

## `codec`

`codec` 決定 `s3` 來源如何格式化寫入每個 S3 物件的資料。

### `avro` 編解碼器

`avro` 編解碼器會將事件寫成 [Apache Avro](https://avro.apache.org/) 文件。由於 Avro 需要結構描述，您可以自行定義結構描述，或讓 Data Prepper 自動產生。建議自行定義結構描述，因為這樣可以針對您的特定使用情境加以調整。

當您提供自己的 Avro 結構描述時，該結構描述會定義資料的最終結構。任何傳入事件中未對應到 Avro 結構描述的額外值，都不會包含在最終目的地中。Data Prepper 不允許在自訂結構描述時使用 `include_keys` 或 `exclude_keys`，以避免自訂 Avro 結構描述與 `include_keys` 或 `exclude_keys` 接收端組態之間的混淆。

當您的資料是同質的，您可以自動產生結構描述。自動產生的結構描述以編解碼器收到的第一個事件為基礎。結構描述只會包含該事件中的鍵，且所有鍵都必須存在於所有事件中，才能自動產生可用的結構描述。自動產生的結構描述會將所有欄位設為可為 null。使用 `include_keys` 和 `exclude_keys` 接收端組態來控制自動產生的結構描述中包含哪些資料。

Avro 欄位應使用 null [聯集](https://avro.apache.org/docs/1.12.0/specification/#unions)，因為這樣可以允許缺少值。否則，每個事件都必須包含所有必要欄位。僅在確定欄位一定存在時才使用不可為 null 的欄位。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`schema` | 是 | 字串 | Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。若 `auto_schema` 設為 true 則不需要。
`auto_schema` | 否 | 布林值 | 設為 `true` 時，會從第一個事件自動產生 Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。
 
### `ndjson` 編解碼器

`ndjson` 編解碼器會將每一行寫成一個 JSON 物件。`ndjson` 編解碼器不接受任何組態。

### `json` 編解碼器

`json` 編解碼器會將事件寫入單一大型 JSON 檔案。每個事件會寫入 JSON 陣列中的一個物件。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`key_name` | 否 | 字串 | JSON 陣列的鍵名稱。預設為 `events`。

### `parquet` 編解碼器

`parquet` 編解碼器會將事件寫入 Parquet 檔案。使用此編解碼器時，請將 `buffer_type` 設為 `in_memory`。

`parquet` 編解碼器會使用結構描述寫入資料。由於 Parquet 需要 Avro 結構描述，您可以自行定義結構描述，或讓 Data Prepper 自動產生。建議自行定義結構描述，因為這樣可以針對您的特定使用情境加以調整。

如需 Avro 結構描述的詳細資訊，請參閱 [Avro 編解碼器](#avro-codec)。

使用下列選項來設定編解碼器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`schema` | 是 | 字串 | Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。若 `auto_schema` 設為 true 則不需要。
`auto_schema` | 否 | 布林值 | 設為 `true` 時，會從第一個事件自動產生 Avro [結構描述宣告](https://avro.apache.org/docs/1.12.0/specification/#schema-declaration)。

### 使用 Parquet 設定結構描述

下列範例管線顯示如何設定 `s3` 接收端，以使用 [VPC Flow Logs](https://docs.aws.amazon.com/vpc/latest/userguide/flow-logs.html#flow-log-records) 的結構描述將 Parquet 資料寫入 Parquet 檔案：

```yaml
pipeline:
  ...
  sink:
    - s3:
        aws:
          region: us-east-1
          sts_role_arn: arn:aws:iam::123456789012:role/Data-Prepper
        bucket: mys3bucket
        object_key:
          path_prefix: vpc-flow-logs/%{yyyy}/%{MM}/%{dd}/%{HH}/
        codec:
          parquet:
            schema: >
              {
                "type" : "record",
                "namespace" : "org.opensearch.dataprepper.examples",
                "name" : "VpcFlowLog",
                "fields" : [
                  { "name" : "version", "type" : ["null", "string"]},
                  { "name" : "srcport", "type": ["null", "int"]},
                  { "name" : "dstport", "type": ["null", "int"]},
                  { "name" : "accountId", "type" : ["null", "string"]},
                  { "name" : "interfaceId", "type" : ["null", "string"]},
                  { "name" : "srcaddr", "type" : ["null", "string"]},
                  { "name" : "dstaddr", "type" : ["null", "string"]},
                  { "name" : "start", "type": ["null", "int"]},
                  { "name" : "end", "type": ["null", "int"]},
                  { "name" : "protocol", "type": ["null", "int"]},
                  { "name" : "packets", "type": ["null", "int"]},
                  { "name" : "bytes", "type": ["null", "int"]},
                  { "name" : "action", "type": ["null", "string"]},
                  { "name" : "logStatus", "type" : ["null", "string"]}
                ]
              }
        threshold:
          event_count: 500000000
          maximum_size: 20mb
          event_collect_timeout: PT15M
        buffer_type: in_memory
```
