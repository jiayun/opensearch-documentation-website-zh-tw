# 剖析 XML 處理器

`parse_xml` 處理器會剖析事件的 XML 資料。

## 組態

您可以使用下列選項設定 `parse_xml` 處理器。

| 選項 | 必要 | 類型 | 說明 |
| :--- | :--- | :--- | :--- | 
| `source` | 否 | 字串 | 指定要剖析的 `event` 欄位。 |
| `destination` | 否 | 字串 | 剖析後 XML 的目的地欄位。預設為 `event` 的根。不可為 `""`、`/` 或任何僅含空白字元的字串，因為這些都不是有效的 `event` 欄位。 |
| `pointer` | 否 | 字串 | 指向要剖析之欄位的 JSON 指標。預設值為 null，表示會剖析整個 `source`。`pointer` 也可以存取 JSON 陣列索引。若 JSON 指標無效，則會將整個 `source` 資料剖析至傳出的 `event` 物件中。若指向的鍵已存在於 `event` 物件中，且 `destination` 為根，則指標會使用該鍵的完整路徑。 |
| `parse_when` | 否 | 字串 | 指定處理器應在何種條件下執行剖析。預設為無條件。接受遵循[運算式語法]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)的 OpenSearch Data Prepper 運算式字串。 |
| `overwrite_if_destination_exists` | 否 | 布林值 | 設為 `true` 時會覆寫目的地。設為 `false` 可避免變更已存在的目的地值。預設為 `true`。 |
| `delete_source` | 否 | 布林值 | 若設為 `true`，則會刪除來源欄位。預設為 `false`。 |
| `tags_on_failure` | 否 | 字串 | 字串清單，指定處理器失敗或剖析期間發生未知例外時，要在事件中設定的標籤。 |
| `handle_failed_events` | 否 | 字串 | 決定如何處理含有 XML 處理錯誤的事件。有效值為 `skip`（記錄錯誤並將事件傳送至下游的下一個處理器）及 `skip_silently`（將事件傳送至下游的下一個處理器，但不記錄錯誤）。預設為 `skip`。 |

## 用法

下列範例示範如何在您的管線中使用 `parse_xml` 處理器。

### 範例：最小組態

下列範例示範 `parse_xml` 處理器的最小組態：

```yaml
parse-xml-pipeline:
  source:
    stdin:
  processor:
    - parse_xml:
        source: "my_xml"
  sink:
    - stdout:
```
{% include copy.html %}

當輸入事件包含下列資料時：

```
{ "my_xml": "<Person><name>John Doe</name><age>30</age></Person>" }
```

處理器會將事件剖析為下列輸出：

```
{ "name": "John Doe", "age": "30" }
```

下表說明常見的[抽象處理器](https://github.com/opensearch-project/data-prepper/blob/main/data-prepper-api/src/main/java/org/opensearch/dataprepper/model/processor/AbstractProcessor.java)指標。

| `timeElapsed` | 計時器 | 表示管線元件執行期間所經過時間的指標。 |

`parse_xml` 處理器包含下列自訂指標。

### 計數器

* `parseErrors`：事件中無效 XML 所造成的剖析錯誤次數。這表示無法剖析該 XML 格式。
* `processingFailures`：`parse_xml` 處理器中發生的處理失敗次數。這表示發生了與無效 XML 格式無關的非預期錯誤。
