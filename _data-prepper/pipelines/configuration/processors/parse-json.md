# 剖析 JSON 處理器

`parse_json` 處理器會剖析事件中 JSON 格式的字串，包括巢狀欄位。它可以選擇使用 JSON 指標擷取來源 JSON 的特定部分，並將擷取的資料新增至事件。

## 組態

您可以使用下列選項設定 `parse_json` 處理器。

| 選項 | 必要 | 類型 | 說明 |
| :--- | :--- | :--- | :--- | 
| `source` | 否 | 字串 | 事件中要剖析的欄位。預設為 `message`。 |
| `destination` | 否 | 字串 | 已剖析 JSON 的目的地欄位。預設為事件的根層級。不可為 `""`、`/` 或任何僅包含空白字元的字串。 |
| `pointer` | 否 | 字串 | 指向來源 JSON 中特定欄位的 JSON 指標（定義於 [RFC 6901](https://datatracker.ietf.org/doc/html/rfc6901)）。若省略，則會剖析整個 `source`。若指標無效，則改為剖析完整的 `source`。寫入根層級目的地時，除非遭到覆寫，否則會保留現有的鍵。 |
| `parse_when` | 否 | 字串 | 決定何時剖析欄位的條件運算式。接受遵循[運算式語法]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)的字串。 |
| `overwrite_if_destination_exists` | 否 | 布林值 | 若目的地欄位已存在，是否加以覆寫。預設為 `true`。 |
| `delete_source` | 否 | 布林值 | 剖析後是否刪除來源欄位。預設為 `false`。 |
| `tags_on_failure` | 否 | 字串 | 剖析失敗或發生非預期例外狀況時要套用的標籤清單。 |
| `handle_failed_events` | 否 | 字串 | 決定如何處理包含 JSON 處理錯誤的事件。有效值為 `skip`（記錄錯誤，並將事件往下游傳送至下一個處理器）和 `skip_silently`（將事件往下游傳送至下一個處理器，但不記錄錯誤）。 |

## 使用方式

若要使用 `parse_json` 處理器，請將其新增至您的 `pipeline.yaml` 組態檔案：

```yaml
parse-json-pipeline:
  source:
    ...
  ...
  processor:
    - parse_json:
```
{% include copy.html %}

所有範例皆使用下列 JSON 訊息作為事件輸出：

```json
{"outer_key": {"inner_key": "inner_value"}}
```
{% include copy.html %}

### 基本範例

下列範例會剖析 JSON 訊息欄位，並將資料扁平化至事件中。範例事件中原始的 `message` 會保留，而剖析後的內容會新增至根層級，如下列輸出所示： 

```json
{
  "message": "{\"outer_key\": {\"inner_key\": \"inner_value\"}}",
  "outer_key": {
    "inner_key": "inner_value"
  }
}
```

### 刪除來源

若您想從原始 JSON 訊息中移除原始欄位，請使用 `delete_source` 選項，如下列範例管線所示：

```yaml
parse-json-pipeline:
  source:
    ...
  ...
  processor:
    - parse_json:
        delete_source: true
```
{% include copy.html %}

在下列事件中，`message` 欄位經過剖析後即被移除，僅留下結構化的輸出：

```json
{
  "outer_key": {
    "inner_key": "inner_value"
  }
}
```


### 使用 JSON 指標的範例

您可以使用 `pointer` 選項從 JSON 資料中擷取特定的巢狀欄位，如下列範例管線所示：

```yaml
parse-json-pipeline:
  source:
    ...
  ...
  processor:
    - parse_json:
        pointer: "/outer_key/inner_key"
```
{% include copy.html %}

只有位於指標路徑 `/outer_key/inner_key` 的值會被擷取並新增至事件。若您設定 `destination`，擷取的值則會改為新增至該欄位：

```json
{
  "message": "{\"outer_key\": {\"inner_key\": \"inner_value\"}}",
  "inner_key": "inner_value"
}
```

| `recordsOut` | 計數器 | 表示記錄從管線元件流出的指標。 |
| `timeElapsed` | 計時器 | 表示管線元件執行期間經過時間的指標。 |

`parse_json` 處理器包含下列自訂指標。

### 計數器

* `parseErrors`：因事件中的 JSON 無效而產生的剖析錯誤數量。這表示無法剖析該 JSON 格式。
* `processingFailures`：`parse_json` 處理器中發生的處理失敗次數。這表示發生了與 JSON 格式無效無關的非預期錯誤。
