# 日期處理器


`date` 處理器會為事件新增預設時間戳記、剖析時間戳記欄位，並將時間戳記資訊轉換為國際標準化組織（ISO）8601 格式。此時間戳記資訊可用作事件時間戳記。

## 組態

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`match` | 視條件而定 | [比對](#Match) | 日期比對組態。此選項不能與 `from_time_received` 同時定義。沒有預設值。
`from_time_received` | 視條件而定 | 布林值 | 當值為 `true` 時，會將事件中繼資料中的時間戳記新增至事件資料，此時間戳記代表來源接收事件的時間。此選項不能與 `match` 同時定義。預設為 `false`。
`date_when` | 否 | 字串 | 指定 `date` 處理器應在何種條件下執行比對。預設沒有條件。
`to_origination_metadata` | 否 | 布林值 | 當值為 `true` 時，也會將比對到的時間以 `Instant` 執行個體的形式新增至事件的中繼資料。預設為 `false`。
`destination` | 否 | 字串 | 用於儲存日期處理器剖析出的時間戳記的欄位。可搭配 `match` 和 `from_time_received` 使用。預設為 `@timestamp`。
`output_format` | 否 | 字串 | 決定新增至事件的時間戳記格式。預設為 `yyyy-MM-dd'T'HH:mm:ss.SSSXXX`。
`source_timezone` | 否 | 字串 | 用於剖析日期的時區，包括無法從值中擷取時區或偏移量的情況。如果時區或偏移量是值的一部分，則會忽略此時區。[資料庫時區清單](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones#List)的 **TZ database name** 欄包含所有可用時區的清單。
`destination_timezone` | 否 | 字串 | 用於將時間戳記儲存至 `destination` 欄位的時區。[資料庫時區清單](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones#List)的 **TZ database name** 欄包含所有可用時區的清單。
`locale` | 否 | 字串 | 用於剖析日期的地區設定。通常用於剖析月份名稱（`MMM`）。此值可包含 IETF BCP 47 中的語言、國家或變體欄位，例如 `en-US`，或 [locale](https://docs.oracle.com/javase/8/docs/api/java/util/Locale.html) 物件的字串表示法，例如 `en_US`。您可以在[語言子標籤註冊表](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry)中找到完整的地區設定欄位清單，包括語言、國家和變體。預設為 `Locale.ROOT`。


### 比對

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`key` | 是 | 字串 | 代表用於比對模式的事件索引鍵。如果設定了 `match`，則為必要。 
`patterns` | 是 | 清單 | 索引鍵的時間戳記值可能採用的模式清單。這些模式以字母和符號序列為基礎。`patterns` 支援 Java [DatetimeFormatter](https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html) 參考文件中列出的所有模式。時間戳記值也支援 `epoch_second`、`epoch_milli` 和 `epoch_nano` 值，分別以自紀元起算的秒數、毫秒數和奈秒數表示時間戳記。紀元值一律使用 UTC 時區。

## 指標

下表說明常見的[抽象處理器](https://github.com/opensearch-project/data-prepper/blob/main/data-prepper-api/src/main/java/org/opensearch/dataprepper/model/processor/AbstractProcessor.java)指標。

| 指標名稱 | 類型 | 說明 |
| ------------- | ---- | -----------|
| `recordsIn` | 計數器 | 表示進入管線元件的記錄數量的指標。 |
| `recordsOut` | 計數器 | 表示離開管線元件的記錄數量的指標。 |
| `timeElapsed` | 計時器 | 表示管線元件執行期間所經過時間的指標。 |

`date` 處理器包含下列自訂指標。

* `dateProcessingMatchSuccessCounter`：傳回符合 `match configuration` 選項所指定至少一個模式的記錄數量。
* `dateProcessingMatchFailureCounter`：傳回不符合 `patterns match` 組態選項所指定任何模式的記錄數量。

## 模式參考

下表提供常見的 `DateTime` 模式。

| 模式                        | 範例                       | 說明                   |
| ------------------------------ | ----------------------------- | ----------------------------- |
| `yyyy-MM-dd'T'HH:mm:ss.SSSXXX` | `2023-03-15T14:30:45.123-05:00` | 含時區的 ISO 8601 格式 |
| `dd/MMM/yyyy:HH:mm:ss Z`       | `15/Mar/2023:14:30:45 -0500`    | Apache 通用記錄檔格式      |
| `MMM dd HH:mm:ss`              | `Mar 15 14:30:45`              | Syslog 格式                 |
| `yyyy-MM-dd HH:mm:ss`          | `2023-03-15 14:30:45`           | 標準 SQL 格式           |
| `MM/dd/yyyy HH:mm:ss`          | `03/15/2023 14:30:45`           | 美國格式                     |

## 紀元模式

下表提供支援的紀元模式。

| 模式        | 說明                                        | 範例值       |
| -------------- | -------------------------------------------------- | ------------------- |
| `epoch_second` | 自 Unix 紀元（`1970-01-01 00:00:00` UTC）起算的秒數 | 1678902000          |
| `epoch_milli`  | 自 Unix 紀元起算的毫秒數                      | 1678902000123       |
| `epoch_micro`  | 自 Unix 紀元起算的微秒數                      | 1678902000123456    |
| `epoch_nano`   | 自 Unix 紀元起算的奈秒數                       | 1678902000123456789 |

每個模式清單僅允許一個紀元模式。若要支援多種紀元格式，請使用個別的日期處理器。

### 使用匯入時間為事件新增預設時間戳記

下列 `date` 處理器組態可用於在 `@timestamp` 欄位中新增套用至所有事件的預設時間戳記：

```yaml
date-ingestion-pipeline:
  source:
    http:
      path: /events
      ssl: false

  processor:
    - date:
        from_time_received: true
        destination: "@timestamp"

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: admin_pass
        index_type: custom
        index: date-ingestion-%{yyyy.MM.dd}
```
{% include copy.html %}

您可以使用下列命令測試此管線：

```bash

  -H "Content-Type: application/json" \
```

### 解析時間戳記以轉換其格式與時區

下列範例示範 `date` 處理器如何使用多個處理器依序解析不同的時間戳記格式 (例如 epoch 毫秒、epoch 秒、ISO 8601 或 Apache Common Log Format)，每個處理器各處理一種特定格式：

```yaml
date-multi-format-pipeline:
  source:
    http:
      path: /events
      ssl: false

  processor:
    # Handle epoch formats (separate processors for different epoch types)
    - date:
        match:
          - key: event_time
            patterns: ["epoch_milli"]
        destination: "@timestamp"
        output_format: yyyy-MM-dd'T'HH:mm:ss.SSSXXX
        source_timezone: UTC
        destination_timezone: America/New_York
        locale: en_US
        date_when: "/event_time != null"
    
    - date:
        match:
          - key: event_time
            patterns: ["epoch_second"]
        destination: "@timestamp"
        output_format: yyyy-MM-dd'T'HH:mm:ss.SSSXXX
        source_timezone: UTC
        destination_timezone: America/New_York
        locale: en_US
        date_when: "/event_time != null and /@timestamp == null"
    
    # Handle ISO format variations in a single processor
    - date:
        match:
          - key: event_time
            patterns: ["yyyy-MM-dd'T'HH:mm:ss.SSSXXX"]
        destination: "@timestamp"
        output_format: yyyy-MM-dd'T'HH:mm:ss.SSSXXX
        source_timezone: UTC
        destination_timezone: America/New_York
        locale: en_US
        date_when: "/event_time != null and /@timestamp == null"
    
    # Handle Apache format variations in a single processor
    - date:
        match:
          - key: event_time
            patterns: ["dd/MMM/yyyy:HH:mm:ss Z"]
        destination: "@timestamp"
        output_format: yyyy-MM-dd'T'HH:mm:ss.SSSXXX
        source_timezone: UTC
        destination_timezone: America/New_York
        locale: en_US
        date_when: "/event_time != null and /@timestamp == null"

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: admin_pass
        index_type: custom
        index: date-multi-format-%{yyyy.MM.dd}
```

### 具有不同日期間距的時間戳記格式

下列範例示範 `date` 處理器如何使用模式變化來處理具有不同日期間距的各種 syslog 時間戳記格式：

```yaml
date-syslog-pipeline:
  source:
    http:
      path: /events
      ssl: false

  processor:
    - date:
        match:
          - key: syslog_timestamp
            patterns: ["MMM d HH:mm:ss", "MMM  d HH:mm:ss", "MMM dd HH:mm:ss"]
        destination: "@timestamp"
        output_format: yyyy-MM-dd'T'HH:mm:ss.SSSXXX
        source_timezone: America/Los_Angeles
        destination_timezone: UTC
        locale: en_US
        date_when: /syslog_timestamp != null
        origination_timestamp_to_metadata: true

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: admin_password
        index_type: custom
        index: date-syslog-%{yyyy.MM.dd}
```
