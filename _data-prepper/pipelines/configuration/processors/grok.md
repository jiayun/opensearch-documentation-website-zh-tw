# Grok 處理器

Grok 處理器使用模式比對，將非結構化資料轉為結構化資料，並從中擷取重要的鍵。

下表說明可搭配 Grok 處理器使用的選項，用來結構化您的資料並讓資料更容易查詢。

`break_on_match` | 否 | 布林值 | 指定是否要比對所有模式 (`true`)，或在找到第一個成功比對後即停止 (`false`)。預設為 `true`。

`named_captures_only` | 否 | 布林值 | 指定是否僅保留具名擷取結果。預設為 `true`。
`pattern_definitions` | 否 | 對應表 | 允許在回應本文內以行內方式使用的自訂模式。預設為空的回應本文。
`patterns_directories` | 否 | 清單 | 指定哪些目錄路徑包含自訂模式檔案。預設為空清單。

## Grok 效能中繼資料

當 `performance_metadata` 選項設定為 `true` 時，`grok` 處理器會將下列中繼資料鍵值加入每個事件：

* `_total_grok_processing_time`：`grok` 處理器比對該事件所花費的總時間，單位為毫秒。這是根據所有在該事件上執行且啟用 `performance_metadata` 選項的 `grok` 處理器所計算的處理時間總和。
* `_total_grok_patterns_attempted`：在該事件上執行的所有 `grok` 處理器中，`grok` 模式比對嘗試的總次數。

若要在事件透過管線傳送至 sink 時包含 Grok 效能中繼資料，請使用 `add_entries` 處理器來描述您要包含的中繼資料，如下列範例所示：


```yaml
  processor:
    - grok:
        performance_metadata: true
        match:
          log: ["%{COMMONAPACHELOG}"]
        break_on_match: true
        named_captures_only: true
        target_key: "parsed"

    - add_entries:
        entries:
          - add_when: 'getMetadata("_total_grok_patterns_attempted") != null'
            key: "grok_patterns_attempted"
            value_expression: 'getMetadata("_total_grok_patterns_attempted")'
          - add_when: 'getMetadata("_total_grok_processing_time") != null'
            key: "grok_time_spent"
            value_expression: 'getMetadata("_total_grok_processing_time")'
```

### 解析 Apache 存取記錄檔

此範例示範解析標準的 Apache HTTP 存取記錄檔，以擷取用戶端 IP、時間戳記、HTTP 方法、URL、狀態碼與回應大小：

```yaml
apache-access-logs-pipeline:
  source:
    http:
      path: /logs
      ssl: false

  processor:
    - grok:
        match:
          message: ['%{COMBINEDAPACHELOG}']
        break_on_match: true
        named_captures_only: true
        keep_empty_captures: false
        target_key: "parsed"

    - date:
        match:
          - key: "/parsed/timestamp"     # JSON Pointer ✔
            patterns: ["dd/MMM/yyyy:HH:mm:ss Z"]
        destination: "@timestamp"
        source_timezone: "UTC"

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: "admin_pass"
        index_type: custom
        index: "apache-logs-%{yyyy.MM.dd}"
```

### 使用自訂模式剖析應用程式記錄檔

此範例示範如何使用使用者定義的模式剖析自訂應用程式記錄檔，以從專有的記錄檔格式擷取結構化資料：

```yaml
application-logs-pipeline:
  source:
    http:
      path: /logs
      ssl: false

  processor:
    - grok:
        match:
          message: ['%{TIMESTAMP_ISO8601:timestamp} \\[%{LOGLEVEL:level}\\] %{DATA:component} - %{GREEDYDATA:details}']
        pattern_definitions:
          LOGLEVEL: (?:INFO|WARN|ERROR|DEBUG|TRACE)
        break_on_match: true
        target_key: "parsed"
        keep_empty_captures: false

    - date:
        match:
          - key: "/parsed/timestamp"
            patterns:
              - "yyyy-MM-dd HH:mm:ss"
              - "yyyy-MM-dd HH:mm:ss.SSS"
        destination: "@timestamp"     # you could also use "/@timestamp"
        source_timezone: "UTC"

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: "admin_pass"
        index_type: custom
        index: "application-logs-%{yyyy.MM.dd}"
```

### 使用多個模式剖析網路裝置記錄檔

此範例示範如何使用多個 `grok` 模式來處理來自網路裝置的不同記錄檔格式，並根據記錄檔類型進行條件式處理：

```yaml
network-device-logs-pipeline:
  source:
    http:
      path: /logs
      ssl: false

  processor:
    - grok:
        match:
          message: [
            # syslog-like
            '%{SYSLOGTIMESTAMP:timestamp} %{SYSLOGHOST:host} %{DATA:program}(?:\\[%{POSINT:pid}\\])?: %{GREEDYDATA:message}',
            # ISO8601 + IP
            '%{TIMESTAMP_ISO8601:timestamp} %{IP:host} %{DATA:program}: %{GREEDYDATA:message}',
            # Cisco style
            '%{CISCO_TIMESTAMP:timestamp}: %{DATA:facility}-%{INT:severity}-%{DATA:mnemonic}: %{GREEDYDATA:message}'
          ]
        break_on_match: true
        named_captures_only: true
        pattern_definitions:
          CISCO_TIMESTAMP: '%{MONTH} %{MONTHDAY} %{TIME}'
        target_key: "parsed"
        timeout_millis: 5000

    # Extract login info from the parsed message text
    - grok:
        match:
          /parsed/message: ['User %{USERNAME:user} logged in from %{IP:source_ip}']
        break_on_match: true
        target_key: "login_info"

    - date:
        match:
          - key: "/parsed/timestamp"
            patterns:
              # syslog-like (no year)
              - "MMM d HH:mm:ss"
              # ISO8601 without/with millis & TZ
              - "yyyy-MM-dd'T'HH:mm:ssXXX"
              - "yyyy-MM-dd'T'HH:mm:ss.SSSXXX"
        destination: "@timestamp"
        source_timezone: "UTC"

  sink:
    - opensearch:
        hosts: ["https://opensearch:9200"]
        insecure: true
        username: admin
        password: "admin_pass"
        index_type: custom
        index: "network-logs-%{yyyy.MM.dd}"
```

## 指標

下表說明常見的[抽象處理器](https://github.com/opensearch-project/data-prepper/blob/main/data-prepper-api/src/main/java/org/opensearch/dataprepper/model/processor/AbstractProcessor.java)指標。

| 指標名稱 | 類型 | 說明 |
| ------------- | ---- | -----------|
| `recordsIn` | 計數器 | 代表記錄進入管線元件的指標。 |
| `recordsOut` | 計數器 | 代表記錄離開管線元件的指標。 |
| `timeElapsed` | 計時器 | 代表管線元件執行期間所經過時間的指標。 |

Grok 處理器包含下列自訂指標。

### 計數器

* `grokProcessingMismatch`：記錄未符合 match 欄位中任何指定模式的記錄數量。
* `grokProcessingMatch`：記錄至少符合 `match` 欄位中一個模式的記錄數量。
* `grokProcessingErrors`：記錄處理記錄時發生錯誤的總數。
* `grokProcessingTimeouts`：記錄比對時逾時的記錄總數。

### 計時器

* `grokProcessingTime`：個別記錄與 `match` 模式比對所花費的時間。`avg` 指標是此計時器最有用的指標，因為它提供記錄比對的平均時間。
