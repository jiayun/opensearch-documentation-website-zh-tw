# Parse Ion 處理器

`parse_ion` 處理器會解析 [Amazon Ion](https://amazon-ion.github.io/ion-docs/) 資料。

## 組態

您可以使用下列選項來設定 `parse_ion` 處理器。

| 選項 | 必要 | 類型 | 說明 |
| :--- | :--- | :--- | :--- | 
| `source` | 否 | 字串 | 要解析的 `event` 中的欄位。預設值為 `message`。 |
| `destination` | 否 | 字串 | 解析後 JSON 的目標欄位。預設為 `event` 的根層級。不能是 `""`、`/` 或任何僅含空白字元的 `string`，因為這些不是有效的 `event` 欄位。 |
| `pointer` | 否 | 字串 | 指向要解析之欄位的 JSON 指標。預設沒有 `pointer`，表示會解析整個 `source`。`pointer` 也可以存取 JSON 陣列索引。如果 JSON 指標無效，則會將整個 `source` 資料解析到輸出的 `event` 中。如果指向的鍵已存在於 `event` 中，且 `destination` 是根層級，則指標會使用該鍵的完整路徑。 |
| `parse_when` | 否 | 字串 | 指定處理器應在何種條件下執行解析。預設為無條件。接受遵循[運算式語法]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/expression-syntax/)的 OpenSearch Data Prepper 運算式字串。 |

| `delete_source` | 否 | 布林值 | 設為 `true` 時，來源欄位會被刪除。預設值為 `false`。 |
| `tags_on_failure` | 否 | 字串 | 字串清單，指定當處理器失敗或解析期間發生未知例外狀況時要設定的標籤。 |
| `handle_failed_events` | 否 | 字串 | 決定如何處理包含 Ion 處理錯誤的事件。有效值為 `skip` (記錄錯誤並將事件往下游傳送至下一個處理器) 和 `skip_silently` (不記錄錯誤，直接將事件往下游傳送至下一個處理器)。預設為 `skip`。 |

## 用法

下列範例示範如何在管線中使用 `parse_ion` 處理器。

### 範例：最小組態

下列範例顯示 `parse_ion` 處理器的最小組態：

```yaml
parse-json-pipeline:
  source:
    stdin:
  processor:
    - parse_json:
        source: "my_ion"
  sink:
    - stdout:
```
{% include copy.html %}

當輸入事件包含下列資料時：

```
{"my_ion": "{ion_value1: \"hello\", ion_value2: \"world\"}"}
```

處理器會將事件解析為下列輸出：

```
{"ion_value1": "hello", "ion_value2" : "world"}
```

下表說明常見的 [Abstract processor](https://github.com/opensearch-project/data-prepper/blob/main/data-prepper-api/src/main/java/org/opensearch/dataprepper/model/processor/AbstractProcessor.java) 指標。

| `recordsOut` | Counter | 代表記錄離開管線元件的指標。 |
| `timeElapsed` | Timer | 代表管線元件執行期間所經過時間的指標。 |

`parse_ion` 處理器包含下列自訂指標。

### Counter

* `parseErrors`：事件中因 Ion 格式無效而導致的解析錯誤數量。表示 Ion 格式無法解析。
* `processingFailures`：`parse_ion` 處理器中發生的處理失敗次數。表示與無效 Ion 格式無關的意外錯誤。
