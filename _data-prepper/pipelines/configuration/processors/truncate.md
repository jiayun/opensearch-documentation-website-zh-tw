# Truncate 處理器

`truncate` 處理器會根據處理器的組態，從值的開頭、結尾或兩側截斷鍵的值。如果鍵的值是清單，則字串清單中的每個成員都會被截斷。清單中的非字串成員不會被截斷。當提供 `truncate_when` 選項時，只有在所指定的條件對正在處理的事件為 `true` 時，才會截斷輸入。

## 組態

您可以使用下列選項來設定 `truncate` 處理器。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`entries` | 是 | 字串清單 | 要新增至事件的項目清單。
`source_keys` | 否 | 字串清單 | 將由處理器修改的來源鍵清單。預設值為空清單，表示所有值都會被截斷。
`truncate_when` | 否 | 條件運算式 | 條件運算式，在符合時決定何時執行截斷作業。
`start_at` | 否 | 整數 | 從字串值的哪個位置開始截斷。預設為 `0`，表示從每個鍵值的開頭開始截斷。
`length` | 否 | 整數| 截斷後的字串長度。未指定時，處理器會根據字串結尾的位置來測量長度。

組態中必須包含 `start_at` 或 `length` 選項其中之一，`truncate` 處理器才能執行。您可以在組態中同時定義這兩個值，以進一步自訂字串中發生截斷的位置。

## 用法

下列範例顯示如何在 `pipeline.yaml` 檔案中設定 `truncate` 處理器：

## 範例：最小組態

下列範例顯示 `truncate` 處理器的最小組態：

```yaml
pipeline:
  source:
    file:
      path: "/full/path/to/logs_json.log"
      record_type: "event"
      format: "json"
  processor:
    - truncate:
        entries:
          - source_keys: ["message1", "message2"]
            length: 5
          - source_keys: ["info"]
            length: 6
            start_at: 4
          - source_keys: ["log"]
            start_at: 5
  sink:
    - stdout:
```

例如，下列事件包含數個具有字串值的鍵：

```json
{"message1": "hello,world", "message2": "test message", "info", "new information", "log": "test log message"}
```

`truncate` 處理器會產生下列輸出，其中：

- `message1` 與 `message 2` 鍵的 `start_at` 設定為 `0`，表示截斷將從字串開頭開始，並將字串本身截斷至長度 `5`。
- `info` 鍵的 `start_at` 設定為 `4`，表示截斷將從字串的字母 `i` 開始，並將字串截斷至長度 `6`。
- `log` 鍵的 `start_at` 設定為 `5`，未指定長度，表示截斷將從字串的字母 `l` 開始。

```json
{"message1":"hello", "message2":"test ", "info":"inform", "log": "log message"}
```


## 範例：使用 `truncate_when`

下列範例組態顯示設定了 `truncate_when` 選項的 `truncate` 處理器：

```yaml
pipeline:
  source:
    file:
      path: "/full/path/to/logs_json.log"
      record_type: "event"
      format: "json"
  processor:
    - truncate:
        entries:
          - source_keys: ["message"]
            length: 5
            start_at: 8
            truncate_when: '/id == 1'
  sink:
    - stdout:
```

下列範例包含兩個事件：

```json
{"message": "hello, world", "id": 1}
{"message": "hello, world,not-truncated", "id": 2}
```

當 `truncate` 處理器在這些事件上執行時，只有第一個事件會被截斷，因為 `id` 鍵的值為 `1`：

```json
{"message": "world", "id": 1}
{"message": "hello, world,not-truncated", "id": 2}
```
