# 服務地圖處理器

`service_map` 處理器使用 OpenTelemetry 資料建立分散式服務地圖，以便在 OpenSearch Dashboards 中進行視覺化。

`service_map` 處理器會產生靜態服務地圖，不會反映拓撲隨時間的變化。新的 [`otel_apm_service_map` 處理器]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/otel-apm-service-map/) 提供以時間為基礎的服務地圖。

選項 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`window_duration` | 否 | 整數 | 評估服務地圖關聯性的固定時間範圍，以秒為單位。預設為 `180`。

## 使用方式

```yaml
entry-pipeline:
   source:
     otel_trace_source:
       path: "/test/path"
   sink:
     - pipeline:
         name: "raw-pipeline"
     - pipeline:
         name: "service-map-pipeline"
raw-pipeline:
   source:
     pipeline:
       name: "entry-pipeline"
   processor:
     - otel_trace_raw:
   sink:
     - opensearch:
         hosts: [<host>]
         index_type: trace-analytics-raw
service-map-pipeline:
   source:
     pipeline:
       name: "entry-pipeline"
   processor:
     - service_map_stateful:
         window_duration: 60s
   sink:
     - opensearch:
         hosts: [<host>]
         index_type: trace-analytics-service-map
```

## 指標

下表說明常見的 [Abstract processor](https://github.com/opensearch-project/data-prepper/blob/main/data-prepper-api/src/main/java/org/opensearch/dataprepper/model/processor/AbstractProcessor.java) 指標。

| 指標名稱 | 類型 | 說明 |
| ------------- | ---- | -----------|
| `recordsIn` | Counter | 記錄進入管線元件的流量。 |
| `recordsOut` | Counter | 記錄離開管線元件的流量。 |
| `timeElapsed` | Timer | 管線元件執行所經過的時間，以毫秒為單位。 |

`service_map` 處理器包含下列自訂指標。

| 指標名稱 | 類型 | 說明 |
| ------------- | ---- | -----------|
| `spansDbSize` | Gauge | 目前與先前 span 資料庫視窗的總大小，以位元組為單位。 |
| `spansDbCount` | Gauge | 目前與先前 span 資料庫視窗中的 span 項目總數。 |
| `traceGroupDbSize` | Gauge | 目前與先前 trace group 資料庫視窗的總大小，以位元組為單位。 |
| `traceGroupDbCount` | Gauge | 目前與先前 trace group 資料庫視窗中的 trace group 項目總數。 |
| `relationshipCount` | Gauge | 已探索並儲存於關聯性狀態中的唯一服務地圖關聯性總數。 |
