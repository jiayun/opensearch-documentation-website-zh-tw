# S3 source

`s3` 是一個從 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) 物件讀取事件的 source 外掛程式。您可以將此 source 設定為使用 [Amazon Simple Queue Service (Amazon SQS)](https://aws.amazon.com/sqs/) 佇列，或掃描 S3 儲存貯體：

- 若要使用 Amazon SQS 通知，請在您的 S3 儲存貯體上設定 S3 事件通知。設定 Amazon SQS 之後，`s3` source 會從 Amazon SQS 接收訊息。當 SQS 訊息指出已建立 S3 物件時，`s3` source 會載入這些 S3 物件，然後使用設定的 [codec](#codec) 進行剖析。
- 若要使用 S3 儲存貯體，請將 `s3` source 設定為使用 Amazon S3 Select 而非 OpenSearch Data Prepper 來剖析 S3 物件。

## IAM 權限

若要使用 `s3` source，請設定您的 AWS Identity and Access Management (IAM) 權限，以授予 Data Prepper 存取 Amazon S3 的權限。您可以使用類似下列 JSON 組態的組態：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "s3-access",
            "Effect": "Allow",
            "Action": [
              "s3:GetObject",
              "s3:ListBucket",
              "s3:DeleteObject"
            ],
            "Resource": "arn:aws:s3:::<YOUR-BUCKET>/*"
        },
        {
            "Sid": "sqs-access",
            "Effect": "Allow",
            "Action": [
                "sqs:ChangeMessageVisibility",
                "sqs:DeleteMessage",
                "sqs:ReceiveMessage"
            ],
            "Resource": "arn:aws:sqs:<YOUR-REGION>:<123456789012>:<YOUR-SQS-QUEUE>"
        },
        {
            "Sid": "kms-access",
            "Effect": "Allow",
            "Action": "kms:Decrypt",
            "Resource": "arn:aws:kms:<YOUR-REGION>:<123456789012>:key/<YOUR-KMS-KEY>"
        }
    ]
}
```

如果您的 S3 物件或 Amazon SQS 佇列未使用 [AWS Key Management Service (AWS KMS)](https://aws.amazon.com/kms/)，請移除 `kms:Decrypt` 權限。

如果您未啟用 `visibility_duplication_protection`，可以從 SQS 佇列的存取權中移除 `sqs:ChangeMessageVisibility` 權限。

## 跨帳戶 S3 存取<a name="s3_bucket_ownership"></a>

當 Data Prepper 從 S3 儲存貯體擷取資料時，會使用
[bucket owner condition](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucket-owner-condition.html) 驗證儲存貯體的擁有權。
預設情況下，Data Prepper 預期 S3 儲存貯體的擁有者與相關 SQS 佇列的擁有者相同。
未提供 SQS 時，Data Prepper 會使用 `aws` 組態中的 Amazon Resource Name (ARN) 角色。

如果您計畫從多個 S3 儲存貯體匯入資料，但每個儲存貯體都與不同的 S3 帳戶相關聯，則需要設定 Data Prepper 以根據下列條件檢查跨帳戶 S3 存取：

- 如果您想取得資料的所有 S3 儲存貯體都屬於 SQS 佇列以外的帳戶，請將 `default_bucket_owner` 設定為儲存貯體帳戶持有人的帳戶 ID。
- 如果您的 S3 儲存貯體位於多個帳戶中，請使用 `bucket_owners` 對應。

在下列範例中，SQS 佇列由帳戶 `000000000000` 擁有。SQS 佇列包含來自兩個 S3 儲存貯體 `my-bucket-01` 和 `my-bucket-02` 的資料。
由於 `my-bucket-01` 由 `123456789012` 擁有，而 `my-bucket-02` 由 `999999999999` 擁有，因此 `bucket_owners` 對應會以帳戶 ID 呼叫兩個儲存貯體擁有者，如下列組態所示：

```
s3:
  sqs:
      queue_url: "https://sqs.us-east-1.amazonaws.com/000000000000/MyQueue"
  bucket_owners:
    my-bucket-01: 123456789012
    my-bucket-02: 999999999999
```

您可以同時使用 `bucket_owners` 和 `default_bucket_owner`。

## 組態

您可以使用下列參數來設定 `s3` source。

參數 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`notification_type` | 是 | 字串  | 必須為 `sqs`。
`notification_source` | 否 | 字串 | 決定 SQS 接收通知的方式。必須為 `s3` 或 `eventbridge`。`s3` 代表從 Amazon S3 直接傳送到 Amazon SQS 的通知，或從 Amazon S3 經由 Amazon Simple Notification Service (Amazon SNS) 傳送到 Amazon SQS 的 fanout 通知。`eventbridge` 代表來自 [Amazon EventBridge](https://aws.amazon.com/eventbridge/) 和 [Amazon Security Lake](https://aws.amazon.com/security-lake/) 的通知。預設為 `s3`。 
`compression` | 否 | 字串  | 要套用的壓縮演算法：`none`、`gzip`、`snappy` 或 `automatic`。預設為 `none`。
`codec` | 是 | Codec  | 要套用的 [codec](#codec)。 
`sqs` | 是 | SQS | SQS 組態。如需更多資訊，請參閱 [`sqs`](#sqs)。
`aws` | 是 | AWS | AWS 組態。如需更多資訊，請參閱 [`aws`](#aws)。
`on_error` | 否 | 字串 | 決定如何處理 Amazon SQS 中的錯誤。可為 `retain_messages` 或 `delete_messages`。`retain_messages` 會將訊息留在 Amazon SQS 佇列中，並嘗試重新傳送訊息。建議用於死信佇列 (DLQ)。`delete_messages` 會刪除失敗的訊息。預設為 `retain_messages`。
`buffer_timeout` | 否 | 持續時間  | 在發生逾時之前，允許將事件寫入 Data Prepper 緩衝區的時間量。Amazon S3 source 在指定時間內無法寫入緩衝區的任何事件都會被捨棄。預設為 `10s`。
`records_to_accumulate` | 否 | 整數  | 在寫入緩衝區之前累積的訊息數量。預設為 `100`。
`metadata_root_key` | 否 | 字串 | 用於將 S3 中繼資料新增至每個事件的基礎索引鍵。中繼資料包含每個 S3 物件的索引鍵與儲存貯體。預設為 `s3/`。
`default_bucket_owner` | 否 | 字串 | S3 儲存貯體擁有者的 AWS 帳戶 ID。如需更多資訊，請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。
`bucket_owners` | 否 | Map  | 儲存貯體名稱的對應，其中包含擁有這些儲存貯體之帳戶的 ID。如需更多資訊，請參閱[跨帳戶 S3 存取](#s3_bucket_ownership)。
`disable_bucket_ownership_validation` | 否 | 布林值  | 當為 `true` 時，S3 source 不會嘗試驗證儲存貯體是否由預期的帳戶所擁有。預期的帳戶是指擁有 Amazon SQS 佇列的同一個帳戶。預設為 `false`。
`acknowledgments` | 否 | 布林值  | 當為 `true` 時，啟用 `s3` source 在 OpenSearch sinks 接收到事件時接收[端對端確認]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/pipelines#end-to-end-acknowledgments)。
`s3_select` | 否 | [s3_select](#s3_select) | Amazon S3 Select 組態。
`scan` | 否 | [scan](#scan) | S3 scan 組態。
`delete_s3_objects_on_read` | 否 | 布林值 | 當為 `true` 時，S3 scan 會在所有 sinks 成功確認來自 S3 物件的所有事件之後，嘗試刪除該 S3 物件。刪除 S3 物件時應啟用 `acknowledgments`。預設為 `false`。
`workers` | 否 | 整數 | 設定 source 用來從 S3 讀取資料的工作執行緒數量 (1--10)。除非您的 S3 物件大小小於 1 MB，否則請將此值保留為預設值。較大的 S3 物件可能會降低效能。此設定會影響以 SQS 為基礎的 source 與 S3-Scan source。預設為 `1`。

## sqs
<!-- vale on -->

下列參數可讓您設定 `s3` 來源外掛程式如何使用 Amazon SQS。

參數 | 必要 | 類型 | 描述
:--- | :--- | :--- | :---
`queue_url` | 是 | 字串 | 接收訊息的 Amazon SQS 佇列 URL。
`maximum_messages` | 否 | 整數 | 每次請求從 Amazon SQS 佇列接收的訊息數量上限。預設為 `10`。
`visibility_timeout` | 否 | 持續時間 | 套用至從 Amazon SQS 佇列讀取之訊息的可見性逾時。此參數應設為 Data Prepper 讀取一個批次中所有 S3 物件可能需要的時間。如果處理時間超過此逾時，且未啟用 `visibility_duplication_protection`，訊息會再次出現在佇列中並可能被重新處理，進而在接收器中產生重複資料。最大值為 12 小時（`43200s`）。預設為 `30s`。
`wait_time` | 否 | 持續時間 | 在 Amazon SQS API 上進行長輪詢時的等待時間。預設為 `20s`。
`poll_delay` | 否 | 持續時間 | 在讀取並處理一批 Amazon SQS 訊息之後、發出下一個請求之前的延遲時間。預設為 `0s`。
`visibility_duplication_protection` | 否 | 布林值 | 若設為 `true`，Data Prepper 會延長 SQS 訊息的可見性逾時，以嘗試避免重複處理。在資料抵達接收器之前，Data Prepper 會定期呼叫 `ChangeMessageVisibility`，以避免重新讀取 S3 物件。此選項僅在 `s3` 來源啟用 `acknowledgments` 時才會生效，因為可見性逾時是透過端對端確認來延長的。未啟用 `acknowledgments` 時，即使此選項設為 `true`，也不會延長可見性逾時。若要使用此功能，您必須在 IAM 角色上授予 `sqs:ChangeMessageVisibility` 的權限。預設為 `false`。
`visibility_duplicate_protection_timeout` | 否 | 持續時間 | 設定使用 `visibility_duplication_protection` 時，訊息不會被處理的總時間上限。最小值為 `30s`，最大值為 24 小時（`86400s`）。預設為 2 小時（`7200s`）。
`max_receive_attempts` | 否 | 整數 | 訊息在自動刪除之前，可從佇列接收的次數上限。當訊息的接收次數超過此數值時，Data Prepper 會將其從佇列中刪除。這有助於避免反覆失敗的訊息阻塞佇列。最小值為 `1`。設定此選項時，對於已接收超過一次的訊息，不會記錄 `sqsMessageDelay` 指標。預設為停用。

## codec
<!-- vale on -->

`codec` 決定 `s3` 來源如何剖析每個 Amazon S3 物件。若要提升效能並提高效率，您可以將[編解碼器組合]({{site.url}}{{site.baseurl}}/data-prepper/common-use-cases/codec-processor-combinations/)與特定處理器搭配使用。

### `newline` 編解碼器

`newline` 編解碼器會將每一行剖析為一個記錄事件。這非常適合大多數應用程式記錄檔，因為每個事件都是逐行剖析。它也適用於每一行各包含一個 JSON 物件的 S3 物件，搭配 [parse_json]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/parse-json/) 處理器剖析每一行時效果很好。

使用下列參數設定 `newline` 編解碼器。

參數 | 必要 | 類型    | 描述
:--- | :--- |:--------| :---
`skip_lines` | 否 | 整數 | 建立事件前要略過的行數。您可以使用此組態略過常見的標頭列。預設為 `0`。
`header_destination` | 否 | 字串  | 指派給 S3 物件標頭行的鍵值。若指定此參數，則每個事件都會包含 `header_destination` 欄位。

<!-- vale off -->
### json 編解碼器
<!-- vale on -->

`json` 編解碼器會將每個 S3 物件剖析為 JSON 陣列中的單一 JSON 物件，接著為陣列中的每個物件建立一個 Data Prepper 記錄事件。

使用下列參數設定 `json` 編解碼器。

參數 | 必要 | 類型    | 描述
:--- | :--- |:--------| :---
`key_name` | 否 | 字串  | 要從中擷取 JSON 陣列並建立事件的輸入欄位名稱。

<!-- vale off -->
### csv 編解碼器
<!-- vale on -->

`csv` 編解碼器會剖析逗號分隔值（CSV）格式的物件，每一列會產生一個 Data Prepper 記錄事件。

使用下列參數設定 `csv` 編解碼器。

參數 | 必要 | 類型   | 描述
:--- |:---------|:------------| :---
`delimiter` | 是 | 整數  | 分隔欄的分隔符號。預設為 `,`。
`quote_character` | 是  | 字串  | 用作 CSV 資料文字限定符號的字元。預設為 `"`。
`header` | 否   | 字串清單 | 包含用於剖析 CSV 資料之欄名稱的標頭。
`detect_header` | 否   | 布林值   | 是否將 Amazon S3 物件的第一行解讀為標頭。預設為 `true`。

### `otel_traces` 編解碼器

`otel_traces` 編解碼器會將每個 S3 物件剖析為 OpenTelemetry 追蹤記錄，並為每筆 span 記錄建立一個 Data Prepper span 事件。

使用下列參數設定 `otel_traces` 編解碼器。

參數 | 必要 | 類型    | 描述
:--- | :--- |:--------| :---
`format` | 否 | 字串 | 指定 OpenTelemetry 追蹤的格式。有效值為 `json` 和 `protobuf`。預設為 `json`。
`otel_format` | 否 | 字串 | 指定解碼後 span 的輸出格式。有效值為 `opensearch` 和 `otel`。預設為 `opensearch`。
`length_prefixed_encoding` | 否 | 布林值 | 指定在 protobuf 格式中，長度是否位於資料之前。預設為 `false`。

## 搭配 `s3` 來源使用 `scan`<a name="scan"></a>
下列參數可讓您掃描 S3 物件。所有參數都可以在儲存貯體層級設定。

參數 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`start_time` | 否  | 字串 | 開始掃描在給定 `start_time` 之後修改之物件的時間。應遵循 [ISO LocalDateTime](https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html#ISO_LOCAL_DATE_TIME) 格式，例如 `023-01-23T10:00:00`。如果 `end_time` 與 `start_time` 一起設定，則會處理 `start_time` 之後且 `end_time` 之前的所有物件。`start_time` 與 `range` 不能一起使用。 
`end_time` | 否 | 字串  | 在給定 `end_time` 之後不再掃描物件的時間。應遵循 [ISO LocalDateTime](https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html#ISO_LOCAL_DATE_TIME) 格式，例如 `023-01-23T10:00:00`。如果 `start_time` 與 `end_time` 一起設定，則會處理 `start_time` 之後且 `end_time` 之前的所有物件。`end_time` 與 `range` 不能一起使用。 
`range` | 否  | 字串 | 從所有儲存貯體掃描物件的時間範圍。支援 ISO_8601 表示法字串，例如 `PT20.345S` 或 `PT15M`，以及秒 (`60s`) 與毫秒 (`1600ms`) 的表示法字串。`start_time` 與 `end_time` 不能與 `range` 一起使用。  範圍 `P12H` 會掃描從管線啟動時間起過去 12 小時內修改的所有物件。 
`buckets` | 是  | 清單 | 要掃描的[掃描儲存貯體](#scan-bucket)清單。
`scheduling` | 否  | 清單 | 對所有儲存貯體排程定期掃描的組態。如果設定了排程，則不能使用 `start_time`、`end_time` 與 `range`。

### scan bucket
<!-- vale on -->

參數 | 必要 | 類型 | 說明
:--- | :--- |:-----| :---
`bucket` | 是 | Map  | 提供每個儲存貯體的參數。

您可以在 `bucket` 設定對應中設定下列參數。

參數 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`name` | 是 | 字串   | 代表要掃描之 S3 儲存貯體名稱的字串。
`filter` | 否 | [Filter](#filter) | 提供篩選組態。
`processing_conditions` | 否 | 清單 | 必須在處理 S3 物件之前滿足的條件清單。每個條件會下載位於同一 S3 目錄中的伴隨物件，並對其內容評估 `when` 運算式。若有任何條件未滿足，S3 物件的處理將被延後並重試。條件會針對每個 S3 物件評估一次，而不是針對每筆記錄。請參閱 [processing_conditions](#processing_conditions)。
`start_time` | 否  | 字串 | 開始掃描在給定 `start_time` 之後修改之物件的時間。應遵循 [ISO LocalDateTime](https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html#ISO_LOCAL_DATE_TIME) 格式，例如 `023-01-23T10:00:00`。如果 `end_time` 與 `start_time` 一起設定，則會處理 `start_time` 之後且 `end_time` 之前的所有物件。`start_time` 與 `range` 不能一起使用。這會覆寫 [scan](#scan) 層級的 `start_time`。
`end_time` | 否 | 字串  | 在給定 `end_time` 之後不再掃描物件的時間。應遵循 [ISO LocalDateTime](https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html#ISO_LOCAL_DATE_TIME) 格式，例如 `023-01-23T10:00:00`。如果 `start_time` 與 `end_time` 一起設定，則會處理 `start_time` 之後且 `end_time` 之前的所有物件。這會覆寫 [scan](#scan) 層級的 `end_time`。
`range` | 否  | 字串  | 從所有儲存貯體掃描物件的時間範圍。支援 ISO_8601 表示法字串，例如 `PT20.345S` 或 `PT15M`，以及秒 (`60s`) 與毫秒 (`1600ms`) 的表示法字串。`start_time` 與 `end_time` 不能與 `range` 一起使用。  範圍 `P12H` 會掃描從管線啟動時間起過去 12 小時內修改的所有物件。這會覆寫 [scan](#scan) 層級的 `range`。

### processing_conditions
<!-- vale on -->

請在每個 `processing_conditions` 項目中使用下列參數。

參數 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`object_name` | 是 | 字串 | 位於與資料物件同一 S3 目錄中的伴隨物件名稱 (例如 `_SUCCESS` 或 `manifest.json`)。伴隨物件會被下載並針對 `when` 運算式進行評估。
`when` | 是 | 字串 | 針對伴隨物件內容評估的 Data Prepper 運算式。只有當此運算式評估為 `true` 時，才會處理 S3 資料物件。例如 `/status == "complete"`。
`applicable_prefix` | 否 | 清單 | S3 索引鍵字首字串清單。只有當物件的索引鍵以這些字首中至少一個開頭時，才會評估該條件。省略時，條件適用於儲存貯體中的所有物件。
`retry_delay` | 否 | 字串 | 條件未滿足時，重新檢查條件前等待的時間長度。支援 ISO 8601 時長格式 (例如 `PT5M`)。最小值為 `PT1M`，最大值為 `PT60M`。預設為 `PT5M`。
`max_retry` | 否 | 整數 | 在不論結果為何仍處理物件之前，重新檢查條件的最大次數。接受 `0` 到 `100` 之間的值。預設為 `10`。達到此上限時，物件將按原樣處理。
`codec` | 否 | Codec | 用於解析伴隨物件的外掛程式編解碼器。設定後，`when` 運算式會針對 `codec` 解析出的第一筆記錄進行評估。省略時，伴隨物件會被解析為扁平 JSON 文件。

下列範例在儲存貯體層級設定 `processing_conditions`：

```yaml
- bucket:
    name: batchinference
    data_selection: data_only
    processing_conditions:
      - object_name: "manifest.json.out"
        when: "/processedRecordCount == /totalRecordCount"
        codec:
          ndjson:
        applicable_prefix:
          - "bedrock-batch-job/output/"
        retry_delay: PT2M
        max_retry: 3
```

### scheduling
<!-- vale on -->

參數 | 必要 | 類型 | 說明
:--- | :--- | :--- | :---
`interval` | 是  | 字串 | 指出每次掃描之間的最小間隔。間隔中的下一次掃描會在上一次掃描結束後經過間隔時間，且上一次掃描的所有物件皆已處理完畢後開始。支援 ISO 8601 標記法字串，例如 `PT20.345S` 或 `PT15M`，以及秒（`60s`）與毫秒（`1600ms`）的標記法字串。 
`count` | 否 | 整數 | 指定儲存貯體將被掃描的次數。預設為 `Integer.MAX_VALUE`。


## 指標

`s3` 來源包含下列指標：

### 計數器

* `s3ObjectsFailed`：`s3` 來源無法讀取的 S3 物件數。
* `s3ObjectsNotFound`：`s3` 來源因 S3「Not Found」錯誤而無法讀取的 S3 物件數。這些也會計入 `s3ObjectsFailed`。
* `s3ObjectsAccessDenied`：`s3` 來源因「Access Denied」或「Forbidden」錯誤而無法讀取的 S3 物件數。這些也會計入 `s3ObjectsFailed`。 
* `s3ObjectsSucceeded`：`s3` 來源成功讀取的 S3 物件數。
* `s3ObjectNoRecordsFound`：`s3` 來源導致 0 筆記錄新增至緩衝區的 S3 物件數。
* `s3ObjectsDeleted`：`s3` 來源刪除的 S3 物件數。
* `s3ObjectsDeleteFailed`：`s3` 來源無法刪除的 S3 物件數。
* `s3ObjectsEmpty`：因大小為 `0` 而被視為空白的 S3 物件數。這些物件將被 `s3` 來源略過。
* `sqsMessagesReceived`：`s3` 來源從佇列接收的 Amazon SQS 訊息數。
* `sqsMessagesDeleted`：`s3` 來源從佇列刪除的 Amazon SQS 訊息數。
* `sqsMessagesFailed`：`s3` 來源無法剖析的 Amazon SQS 訊息數。
* `sqsMessagesDeleteFailed` -- `s3` 來源無法從 SQS 佇列刪除的 SQS 訊息數。
* `sqsVisibilityTimeoutChangedCount`：`s3` 來源變更 SQS 訊息可見性逾時的次數。這包含同一訊息的多個可見性逾時變更。
* `sqsVisibilityTimeoutChangeFailedCount`：`s3` 來源無法變更 SQS 訊息可見性逾時的次數。這包含同一訊息的多個可見性逾時變更失敗。
* `acknowledgementSetCallbackCounter`：`s3` 來源收到 Data Prepper 確認的次數。

### 計時器

* `s3ObjectReadTimeElapsed`：測量 `s3` 來源執行 GET S3 物件、剖析該物件，並將事件寫入緩衝區所花費的時間量。
* `sqsMessageDelay`：測量從 S3 建立物件到該物件完全剖析完成所經過的時間。

### 分佈摘要

* `s3ObjectSizeBytes`：測量 S3 `Content-Length` 所回報的 S3 物件大小。對於壓縮物件，這是壓縮後的大小。
* `s3ObjectProcessedBytes`：測量 `s3` 來源針對指定物件所處理的位元組數。對於壓縮物件，這是未壓縮的大小。
* `s3ObjectsEvents`：測量 S3 物件所產生的事件數（有時稱為記錄）。

## 範例：使用 sqs 的未壓縮記錄檔
<!-- vale on -->

下列 pipeline.yaml 檔案顯示讀取未壓縮且以換行符號分隔之記錄檔的最小組態：

```
source:
  s3:
    notification_type: sqs
    codec:
      newline:
    compression: none
    sqs:
      queue_url: "https://sqs.us-east-1.amazonaws.com/123456789012/MyQueue"
    aws:
      region: "us-east-1"
      sts_role_arn: "arn:aws:iam::123456789012:role/Data-Prepper"
```

## 範例：使用 scan 的未壓縮記錄檔

下列 pipeline.yaml 檔案顯示掃描含有未壓縮且以換行符號分隔之記錄檔之物件的最小組態：

```
source:
  s3:
    codec:
      newline:
    compression: none
    aws:
      region: "us-east-1"
      sts_role_arn: "arn:aws:iam::123456789012:role/Data-Prepper"
    scan:
      start_time: 2023-01-01T00:00:00
      range: "P365D"
      buckets:
        - bucket:
            name: "s3-scan-test"
            filter:
              exclude_suffix:
                - "*.log"
```
